### IMPLEMENTATION SUGGESTION
The cleanest way to do this is to create a territory mapping object/config that assigns each city to either "alvin" or "friendswood" and determines the phone number dynamically. For example:

```javascript
const territoryConfig = {
  alvin: { phone: "281-331-5248", label: "Alvin Office" },
  friendswood: { phone: "281-482-8400", label: "Friendswood Service Area" }
};

const cityTerritory = {
  "alvin": "alvin",
  "manvel": "alvin",
  "angleton": "alvin",
  "rosharon": "alvin",
  "sienna": "alvin",
  "friendswood": "friendswood",
  "pearland": "friendswood",
  "clear-lake": "friendswood",
  "league-city": "friendswood",
  "deer-park": "friendswood",
  "pasadena": "friendswood",
  "webster": "friendswood",
  "seabrook": "friendswood",
  "kemah": "friendswood",
  "nassau-bay": "friendswood",
  "la-marque": "friendswood",
  "dickinson": "friendswood"
};
```

This way, when rendering any city page, you just look up the city slug and get the correct phone number automatically.

**IMPORTANT:** The site-wide header should still show BOTH numbers (from Phase 2). This phone routing only applies to the page-specific CTAs, hero sections, and "Call Now" buttons on individual city/service pages.
